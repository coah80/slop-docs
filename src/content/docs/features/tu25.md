Title Update 25 is the **first milestone neoLegacy implements on top of its TU19 base** and is
marked **100% complete** (`README.md:8`). Per the contribution policy, everything before TU25 is
treated as already present in the TU19 base and is not reimplemented unless buggy
(`CONTRIBUTING.md:4`); TU25 is where neoLegacy's own additions begin.

Almost the entire TU25 block content set landed in a single commit,
[`a205b1d7` "Added features from TU25"](https://git.neolegacy.dev/neoStudiosLCE/neoLegacy/commit/a205b1d7)
(piebot, 2026-03-11), which touched 29 files across `Minecraft.World` and `Minecraft.Client`. Its
own commit message enumerates the additions:

> Acacia and Dark Oak Logs, Planks and Stairs. Fences, Fence Gates and Doors for
> Spruce/Birch/Jungle/Acacia/Dark Oak. Iron Trapdoors and Inverted Daylight Sensor.

This page catalogs each addition with its block ID and source location. For how the block registry
itself works, see [Tiles &amp; the block registry](/slop-docs/world/blocks/). For the TU31 milestone
that follows, see [TU31 Backport](/slop-docs/features/tu31/).

## Acacia &amp; Dark Oak wood family

Vanilla LCE TU19 has only the four original wood types in the first log/leaf blocks (id 17 / id 18).
TU25 adds the second "log2"/"leaves2" pair that holds acacia and dark oak, plus their planks (as
metadata on the oak-planks tile) and dedicated stair blocks.

Files: `Minecraft.World/Tile.cpp`, `Minecraft.World/TreeTile.h`, `Minecraft.World/RotatedPillarTile.h`,
`Minecraft.World/WoodTile.cpp`.

| Block | ID | Class / registration | Source |
|---|---|---|---|
| `leaves2` (acacia/dark-oak leaves) | 161 | `LeafTile2(161)`, icon `leaves_acacia` | `Tile.cpp:399` |
| `log2` (acacia/dark-oak log) | 162 | `TreeTile2(162)`, icon `log` | `Tile.cpp:569` |
| Acacia stairs (`woodStairsAcacia`) | 163 | `StairTile(163, Tile::wood, TreeTile::ACACIA_TRUNK)` | `Tile.cpp:570` |
| Dark oak stairs (`woodStairsDark`) | 164 | `StairTile(164, Tile::wood, TreeTile::DARK_TRUNK)` | `Tile.cpp:571` |

The trunk sub-type constants used by the stairs are defined in `TreeTile.h`:

```cpp
static const int ACACIA_TRUNK = 4;   // TreeTile.h:17
static const int DARK_TRUNK   = 5;   // TreeTile.h:18
```

Acacia and dark oak **planks** are not separate tiles — they are metadata values on the existing
oak-planks tile `Tile::wood` (id 5, `Tile.cpp:382`), matching Java/LCE. A later cleanup commit
[`55ce17bc` "change XXX Wood to XXX Planks for accuracy"](https://git.neolegacy.dev/neoStudiosLCE/neoLegacy/commit/55ce17bc)
corrected the display strings from "Wood" to "Planks".

The `log2` item uses a `MultiTextureTileItem` driven by `TreeTile2::TREE_NAMES` so the two variants
share one item id (`Tile.cpp:649`).

## Fences, gates, and doors — per wood type

TU25 gives every non-oak wood its own fence, fence gate, and door. neoLegacy registers these as
distinct tiles with sequential IDs in the 183–197 range. All are wired up in `Tile::staticCtor`
(`Tile.cpp`).

Files: `Minecraft.World/Tile.cpp`, `Minecraft.World/FenceTile.cpp`, `Minecraft.World/FenceGateTile.cpp`,
`Minecraft.World/DoorTile.cpp`, `Minecraft.World/DoorItem.cpp`, `Minecraft.World/Item.cpp`.

## Iron trapdoors

TU25 adds the iron trapdoor as a metal counterpart to the pre-existing wooden trapdoor. Both use the
same `TrapDoorTile` class; the iron one is heavier (5.0 destroy time) and metal-sounding.

Files: `Minecraft.World/TrapDoorTile.cpp`, `Minecraft.World/Tile.cpp`.

| Trapdoor | ID | Registration | Source |
|---|---|---|---|
| Wooden | 96 | `TrapDoorTile(96, Material::wood)`, `SOUND_WOOD`, 3.0 destroy time | `Tile.cpp:489` |
| Iron | 167 | `TrapDoorTile(167, Material::metal)`, `SOUND_METAL`, 5.0 destroy time | `Tile.cpp:574` |

```cpp
// Tile.cpp:574
Tile::iron_trapdoor = (new TrapDoorTile(167, Material::metal))
    ->setBaseItemTypeAndMaterial(Item::eBaseItemType_door, Item::eMaterial_trap)
    ->setDestroyTime(5.0f)->setSoundType(Tile::SOUND_METAL)
    ->setIconName(L"iron_trapdoor")->setDescriptionId(IDS_TILE_IRON_TRAPDOOR)
    ->setNotCollectStatistics()->sendTileData()->setUseDescriptionId(IDS_DESC_TRAPDOOR);
```

## Inverted daylight sensor

Rather than a whole new block class, the inverted daylight sensor is the **same `DaylightDetectorTile`
class with a new `inverted` constructor flag**. The `a205b1d7` change modified the constructor
signature and the signal logic.

Files: `Minecraft.World/DaylightDetectorTile.cpp`, `Minecraft.World/DaylightDetectorTile.h`,
`Minecraft.World/Tile.cpp`.

| Sensor | ID | Registration | Source |
|---|---|---|---|
| Daylight detector | 151 | `DaylightDetectorTile(151, false)` | `Tile.cpp:558` |
| Inverted daylight detector | 178 | `DaylightDetectorTile(178, true)` | `Tile.cpp:587` |

The constructor gained a `bool inverted` parameter; the signal-strength routine subtracts the normal
output from the maximum when inverted, and right-clicking swaps a sensor between the two tile IDs:

```cpp
// DaylightDetectorTile.cpp — updateSignalStrength()
if (inverted)
    target = Redstone::SIGNAL_MAX - target;

// use() — right-click toggles inverted/normal in place
if (inverted)
    level->setTileAndData(x, y, z, Tile::daylightDetector_Id, 0, UPDATE_CLIENTS);
else
    level->setTileAndData(x, y, z, Tile::invertedDaylightDetector_Id, 0, UPDATE_CLIENTS);
```

The inverted texture is registered as `inverted_` + the base icon name, so it draws distinctly
(`DaylightDetectorTile.cpp::registerIcons`). See [Redstone](/slop-docs/world/redstone/) for how the
signal feeds neighbouring blocks.

## TU25 DLC (skin &amp; texture packs)

TU25's downloadable content was added separately from the block code, and needed two attempts. The
sequence in the log:

| Commit | Message |
|---|---|
| [`274b4575`](https://git.neolegacy.dev/neoStudiosLCE/neoLegacy/commit/274b4575) | Add TU25 DLCs |
| `3b5a7e1f` | Revert adding TU25 DLCs |
| [`9f148e8d`](https://git.neolegacy.dev/neoStudiosLCE/neoLegacy/commit/9f148e8d) | Properly add the TU25 DLCs |

The bundled packs (from the `274b4575` file list under `Minecraft.Client/Windows64Media/DLC/`)
include texture packs — **Candy, Cartoon, City, Fantasy** — and skin/mash-up content such as
**Battle and Beasts / Battle and Beasts 2**, **Festive**, and updates to the **Doctor Who Skins
Volume I** and **Festive Skin Pack**. (These are binary `.pck`/`.arc`/`.mcs` media assets and are
not inspected in detail here.)

:::note[Later removals]
The TU31 fishing-fix commit
[`e45633de`](https://git.neolegacy.dev/neoStudiosLCE/neoLegacy/commit/e45633de) later removed the **Greek
Mythology** and **Halloween 2015** DLC packs because they were crashing the game at that point — so
the shipped DLC set is not identical to the full TU25 catalogue.
:::
