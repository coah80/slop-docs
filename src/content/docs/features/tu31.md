Title Update 31 is neoLegacy's largest milestone and, per `README.md:9`, is **97.01% complete** —
the current headline goal of the project. It builds on the completed
[TU25 backport](/slop-docs/features/tu25/). Where TU25 landed in essentially one commit, TU31 is
spread across dozens of feature commits by many contributors and is still receiving fixes.

This page catalogs the TU31 additions with block/entity IDs, source files, and commit hashes. Broad
subsystem detail lives in [Tiles &amp; the block registry](/slop-docs/world/blocks/),
[Entities &amp; mobs](/slop-docs/world/entities/), [Enchantments](/slop-docs/world/enchantments/),
and [World generation](/slop-docs/world/worldgen/).

Most block content merged through
[`a9004f7a` "TU31 final blocks + changes" (#9)](https://git.neolegacy.dev/coah80/neoLegacy/commit/a9004f7a).

## Blocks

### Stone variants — andesite / diorite / granite (+ polished)

These are **not new tiles**. They are the six metadata variants of the existing `StoneTile` (id 1,
`Tile.cpp:378`). The variant table lives in `StoneTile.cpp`:

Files: `Minecraft.World/StoneTile.cpp`, `Minecraft.World/StoneTile.h`.

| Variant | Stone data value | Icon |
|---|---|---|
| Granite | 1 (`GRANITE`) | `stone_granite` |
| Polished granite | 2 (`POLISHED_GRANITE`) | `stone_granite_smooth` |
| Diorite | 3 (`DIORITE`) | `stone_diorite` |
| Polished diorite | 4 (`POLISHED_DIORITE`) | `stone_diorite_smooth` |
| Andesite | 5 (`ANDESITE`) | `stone_andesite` |
| Polished andesite | 6 (`POLISHED_ANDESITE`) | `stone_andesite_smooth` |

Constants at `StoneTile.h:10-15`; name/icon tables at `StoneTile.cpp:7-21`. The **crafting recipes**
for all six (including the 4× polished recipes) were added by
[`dc5ad7aa` "added craft recipes for andesite, diorite and granite (and polished) blocks" (#97)](https://git.neolegacy.dev/coah80/neoLegacy/commit/dc5ad7aa),
which edited `StructureRecipies.cpp`.

### Barrier

A truly indestructible block used for map-making.

Files: `Minecraft.World/BarrierTile.cpp`, `Minecraft.World/BarrierTile.h`,
client `Minecraft.Client/BarrierParticle.cpp`. Commits:
[`950de854` "barrier block"](https://git.neolegacy.dev/coah80/neoLegacy/commit/950de854),
[`a51d7ae8` "barrier block."](https://git.neolegacy.dev/coah80/neoLegacy/commit/a51d7ae8).

```cpp
// Tile.cpp:573
Tile::barrier = (new BarrierTile(166, Material::stone, false))
    ->setIndestructible()->setExplodeable(6000000)
```

## Mobs / entity behaviour

[`d36a027e` "Villagers turn into witches when struck by lightning (#83)"](https://git.neolegacy.dev/coah80/neoLegacy/commit/d36a027e).

Files: `Minecraft.World/Witch.cpp`, client `WitchModel`/`WitchRenderer`. Witch entity type
`eTYPE_WITCH`, numeric id **66** (`EntityIO.cpp:97`).

### Creeper ignition via flint &amp; steel

[`42ee0b51` "Creepers can be ignited with flint and steel (#84)"](https://git.neolegacy.dev/coah80/neoLegacy/commit/42ee0b51).
`Creeper` gains an `ignited` flag; it is also set on lightning strike (`Creeper::thunderHit`,
`Creeper.cpp:189`) and by right-clicking with `Item::flint_and_steel` (`Creeper.cpp:210`).

```cpp
// Creeper.cpp
void Creeper::thunderHit(const LightningBolt *lightningBolt) {   // :189
    Monster::thunderHit(lightningBolt);
    ...
    ignited = true;                                              // :198
}
```
